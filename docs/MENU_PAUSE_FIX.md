# MENU 打开时偶发断连修复

用户报告串流中点 MENU 约六成出现“网络已断开，可重新连接”，重连成功。电脑日志在 PAU3 后约40–110 ms 报原始 `timed out`，而非3秒心跳/帧确认超时。

## 原因与修复

帧发送原本有部分写入与短超时重试，但菜单 NOP3 心跳和 STA3 统计直接调用 sendall，复用了收包线程所需的100 ms socket timeout。S3 进入菜单时可能仍有 JPEG 在途，却已经开始同步绘制本地界面；短时不能收取数据，使控制消息写入阻塞超过100 ms，电脑立即结束连接。

- 所有握手后的控制消息和 JPEG 共用单一发送函数，保留准确的部分发送偏移，短超时重试，防止重发已经写出的前缀。真正无进展时仍按原3秒限时断开。
- S3 发送 PAU3(a=1,b=暂停序号)，进入排空阶段，保持网络读取和触摸抬手心跳，暂不绘制菜单。
- 电脑停止创建新帧，已经开始发送的完整数据包必须发送完，再发送 PAK3(a=同一暂停序号)，形成 TCP 字节流中的暂停确认边界。
- S3 识别匹配的 PAK3，并确认解码/显示已空闲、帧结果已处理后才绘制菜单。后续由 NOP3维持连接。旧暂停序号不能放行新菜单。
- 继续桌面发送 PAU3(a=0,b=暂停序号)，唤醒发送线程；不依赖固定睡眠结束后再恢复。

没有增加每帧握手；暂停确认只在进入菜单/文字页时发生。普通串流性能参数、3秒真实断线检测、Wi-Fi配置、配对和NVS均未改变。两端须一起更新。

## 验证

67项软件测试通过。新增模拟覆盖：控制包与帧的部分发送和短超时、不重复已发送字节、真正3秒无进展仍失败、在途帧排空后确认、连续10轮菜单暂停/恢复，以及菜单停留超过3秒仍通过心跳保持连接。测试使用虚拟鼠标，不注入真实输入。

已编译并烧录 ESP32-S3 应用（1,206,256 bytes），打包电脑软件GUI smoke通过并启动新版。用户在“连续15–20次菜单/继续、一次长停留、文字页返回”的测试请求后确认“连续测试正常，没有断开”。此结果确认本轮用户场景，不替代长期弱网稳定性验证。
