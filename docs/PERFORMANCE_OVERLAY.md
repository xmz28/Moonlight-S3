# 性能浮窗与控件尺寸调整

本轮先更新文档并中文提交旧版本：固件 `595d065`，Windows 端 `ef5bbc6`，随后再修改。

## 操作与布局

底栏六键等宽分配 800 像素，宽度相差最多 1 像素，依次为 LEFT、RIGHT、SCROLL、KEYBOARD、BACK、MENU。逻辑分界为 0/133/266/400/533/666/800，绘制与触摸同步更新。隐藏底栏时保留右下角 MENU。

电脑设置页采用两列四行，所有选项统一 360×54 像素，包括目标帧率和新增性能浮窗开关。两列分别位于 x24 与 x416，行坐标为 y130/194/258/322。

性能浮窗默认关闭，可在电脑设置页保存，也可在串流 MENU 中即时开关，按电脑保存。浮窗固定在桌面左上角，不改变触摸映射。

## 数值含义

- FPS：S3 成功显示的帧数，约一秒采样一次。
- RX Mbps：S3 实际读到的 JPEG 负载字节数×8/时间/1,000,000，代表当前串流接收速率，不是 Wi-Fi 链路协商速度或测速结果。
- Decode：JPEG 解码平均耗时。
- Display：从帧处理开始到 LCD 提交确认的平均耗时，包含解码、放大、浮窗和显示同步，不能与 Decode 相加。
- ACK：电脑端发送帧前至收到 S3 帧确认的时间，保留原电脑界面的定义，不是 ping、单向网络延迟或触摸延迟。
- Errors：本次浮窗统计期间的帧处理错误数；Wi-Fi dBm 为信号强度。

## 开销控制

S3 的面板范围为 232×104，直接复用现有 ASCII 字模。内部 SRAM 保存约3 KB 单色字形掩码与8 KB颜色展开表，最多每秒重新生成一次文字。合成直接写进解码块或放大行的内部 SRAM，再随原有 JPEG 像素一次拷贝到未显示的 framebuffer；不新增一次 PSRAM 覆盖，也不改动正在扫描的画面。关闭时跳过计数与合成，不创建额外任务，不做中文字体分区读取，也不频繁写 NVS。

启动后尚未建立连接时可用 USB `MS3PERF1` 测量相同的掩码生成/逐行合成路径，目标是离屏内部 SRAM 行缓冲，不提交到 LCD。它测的是增加的合成 CPU 时间，不是端到端 FPS；已经发起过连接时拒绝该诊断，需重启后再测，防止与解码任务同时操作缓存。

电脑只在启用时每秒发送一个16-byte STA3 消息，携带当前 ACK 时间和显示状态；关闭时发送一次状态更新。S3 的 OVR3 只控制浮窗显示，不改变输入权限、JPEG 参数或配对。

## 验证

64 项 Windows 回归测试通过，包括相邻 BACK/MENU 命中、统计开关序列化、帧边界与原有输入/会话测试。固件已使用现有共享环境编译并更新应用，配置分区与字库不变。实机开销对照与界面确认结果另行记录，不以编译成功代替实测。

最终启动空闲态实机微基准：首次生成并合成 1073 µs，128 次缓存合成平均 888 µs，最大1092 µs；额外 PSRAM framebuffer 写入为0。LCD仍在正常扫描，调用的是相同内部 SRAM 行合成函数。相对25 FPS的40 ms帧周期，888 µs约占2.2%；这是 CPU 合成时间比例，不等同实测 FPS 降幅。整段 JPEG 串流 A/B 未收到屏上启动操作，未完成，不能给出端到端帧率差异。原始摘要见 [overlay-draw.json](performance/overlay-draw.json)。
